# ADR 0026: Local AI Engine

## Status

Accepted; Codex opt-in superseded by ADR 0032; run command and pairing link amended by ADR 0035; trusted origin (`--site`) amended by ADR 0042. Adds a second provider next to OpenRouter (ADR 0008); OpenRouter stays the default. Revised in the same block after three security reviews (signed and encrypted requests, Codex opt-in, cleanup, atomic queue, process groups and deadlines).

## Context

Many users already pay for Claude (Claude Code) or ChatGPT (Codex CLI). They should be able to read stamps with that subscription instead of buying OpenRouter credits. A browser cannot run those CLIs, and the site is static (ADR 0003), so something has to run on the user's own computer. The maintainer chose a downloadable script (not npm, not Docker) that supports whichever of the two CLIs is installed and logged in.

## Decision

- **Where it lives.** `packages/local/src/voyput-local.ts`, one file using only Node built-ins, Node 22.12 or newer (the repo's `engines`). A package, not a root `local/` folder, because the existing workspace globs already type-check and test `packages/*/src` and `packages/*/test`. The file uses erasable TypeScript only. A small Vite plugin in `apps/web/vite.config.ts` turns it into JavaScript with Vite's own `transformWithOxc` (no Node-version-dependent API, no new dependency) and serves it as `/voyput-local.mjs` (dev server and build output).
- **How it is run.** Settings shows the command, built from the page's origin: `curl -fsSL https://voyput.app.offcall.link/voyput-local.mjs -o voyput-local.mjs && node voyput-local.mjs`, or from a clone `node --experimental-strip-types packages/local/src/voyput-local.ts` (the flag exists from Node 22.6, so it works on the documented 22.12). `--port` changes the port, `--codex` enables Codex.
- **Server.** HTTP on `127.0.0.1` only, default port 47615. `GET /health` returns `{ app, version, engines, maxJobs, proof }`; `POST /extract` takes an encrypted `{ engine: auto|codex|claude, system, text, image }` (image a JPEG or PNG data URL) and returns an encrypted `{ text, engine }` (see Authentication). The app builds the same prompts it sends to OpenRouter and parses the answer with the same core parsers; the script only relays. `auto` uses Claude Code if available, else Codex.
- **Queue and deadline.** At most 3 CLI runs at once (`MAX_JOBS`, equal to Extract's concurrency, reported in `/health`). Admission reserves, from the headers alone and before any body byte is read, a slot in the job line and the body's `Content-Length` in a 64 MB byte budget; both are taken together or not at all, and at most 3 + 6 slots exist, so uploading, waiting and running requests together never exceed 9 and the line never exceeds 6. The slot and bytes stay held until the answer is sent (the body and the decoded photo are in memory until then), and are released on every path, failure included; a further request gets 503. Each request has one deadline of 10 minutes from its arrival that covers the upload, the queue and the run: an upload still arriving at the deadline is cut off (408), a job whose deadline passed while it waited is rejected instead of started (the queue checks the clock when a run frees up, not only its timer), and no CLI is spawned past it. The app waits 11 minutes. A waiting request leaves the line, and a running CLI is killed, when its deadline passes or its client disconnects.
- **CLIs.** Found by walking `PATH` (with `PATHEXT` on Windows). Each job gets a fresh temp dir `voyput-local-<pid>-*` (image and system prompt written mode 0600), deleted afterwards. The CLI gets only an allowlist of environment variables (PATH, HOME/user profile, locale, temp, XDG dirs, D-Bus for keyrings, Windows system dirs, `CODEX_HOME`/`CLAUDE_CONFIG_DIR`, the providers' own API key variables, proxies and CA files). It is spawned detached (its own process group), and the group is killed with SIGKILL whenever the CLI exits, is cancelled or times out, also after the CLI itself is gone, so descendants cannot outlive it. A job settles at most 2 s after that even if something still holds its pipes (they are destroyed), so deadlines and shutdown always finish cleanup. On Windows `taskkill /T /F`, which reaches descendants only while the CLI still runs. Flags verified on this machine against codex-cli 0.169.0 (`codex exec --help`, `codex features list`, `codex debug prompt-input`) and Claude Code 2.1.325 (`claude --help`):
  - `codex exec --sandbox read-only --disable shell_tool --disable view_image -c web_search="disabled" --skip-git-repo-check --ephemeral --ignore-user-config --ignore-rules --color never --cd <tmp> --output-last-message <tmp>/answer.txt --image <tmp>/page.jpg`, prompt (system + text) on stdin. `codex debug prompt-input` (no model call) shows that these flags remove `exec_command`, `write_stdin` and `view_image`. Still offered and not removable by any flag found: a JavaScript `exec` sandbox described as having no filesystem or network, `apply_patch` (writes are blocked by the read-only sandbox), MCP resource readers (no servers are loaded with `--ignore-user-config`), a clock, and sub-agent tools. Codex has no flag found here that restricts reads to the job dir. An unknown `--disable` name makes Codex exit with an error, so a renamed flag fails closed.
  - `claude -p --input-format stream-json --output-format stream-json --verbose --tools "" --system-prompt-file <tmp>/system.txt --no-session-persistence --safe-mode --strict-mcp-config`, one user message with the image as a base64 block and the text on stdin; the answer is the `result` event. Claude gets no tools at all. `--system-prompt-file` is listed only in the help text of `--bare`, not as its own entry; it worked in the smoke run.
  - **Codex is off by default.** Because it cannot be confined as fully as Claude Code, the script offers Codex only when started with `--codex`, and says so on start; Settings says so too.
- **Authentication.** Any website, and any other local user, can reach a localhost port; another user could also bind 47615 while voyput-local is stopped. So the pairing token is a shared secret that never travels after pairing:
  - Every request except CORS preflights carries `X-Voyput-Auth: v3.<ms timestamp>.<nonce>.<sha256 of body>.<mac>`, where `mac` is HMAC-SHA256(token, `voyput-local/3 request`, method, path, timestamp, nonce, body hash, joined by newlines), base64url. The server rejects (401) a missing or malformed header, a timestamp more than 60 s off, a wrong MAC (constant-time compare) or a nonce already used. All of this, plus host, origin, route, `Content-Length` (required, at most 30 MB) and queue room, is checked from the headers before any body byte is read; then the body must match the signed hash.
  - `/health` answers carry `proof` = HMAC-SHA256(token, `voyput-local/3 response`, request nonce, sha256 of `health`). Before each photo, the app calls `/health` with a fresh nonce and checks the proof; if it does not match ("unverified"), nothing is sent and Settings says something else answers on the port.
  - The `/extract` body and its answer are AES-256-GCM messages `{ iv, data }` (12-byte random IV per message, 16-byte tag appended, base64) under a key derived from the token with HKDF-SHA256 (salt `voyput-local/3`, info `aes-256-gcm`). The request's associated data is `voyput-local/3 request`, method, path, timestamp and nonce of its signed header; the answer's is `voyput-local/3 response` and that nonce. So if voyput-local stops between `/health` and `/extract` and something else takes the port, it receives only ciphertext, and an answer it makes up does not decrypt and is dropped. A body sealed for another request, or changed, gets 400.
  - The request MAC stays next to the encryption: it lets the server refuse unauthenticated or replayed requests from headers alone, before reading up to 30 MB, and authenticates `/health`, which has no body. Error answers (401, 4xx, 502 with the CLI's last stderr line) are not encrypted; they carry no photo or result.
  - The app signs and encrypts with WebCrypto (`apps/web/src/ai/localAuth.ts`), the script with `node:crypto`; the app tests drive the script's real request handler to keep the two in step.
  - The token (24 random bytes, base64url) is stored in `$XDG_CONFIG_HOME/voyput-local/token` (default `~/.config`), mode 0600, so the app stays paired across restarts; `--new-token` replaces it. On start the script prints `https://voyput.app.offcall.link/settings#local=<token>` (plus `&port=` when not default). Settings reads the hash, stores token and port, selects Local and removes the hash from the address bar. The token can also be pasted.
  - CORS allows only `https://voyput.app.offcall.link` and `http://localhost:*` / `http://127.0.0.1:*`; other origins get 403 with no CORS headers. Requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` get 403 (DNS rebinding). Private Network Access preflights get `Access-Control-Allow-Private-Network: true`.
  - The log prints method, path, status and seconds only, never bodies, images or answers.
- **Cleanup.** On SIGINT, SIGTERM or SIGHUP the script stops accepting connections and closes the job line: every waiting request is rejected and no queued job may start, and a job between temp dir and spawn stops before spawning. It then kills every running CLI tree, waits until the running jobs have finished and deleted their temp dirs, removes any dir still listed, and exits. On start it deletes `voyput-local-<pid>-*` dirs whose pid is no longer running (left by a crash or `kill -9`).
- **Where the photo goes.** Browser → voyput-local on the same computer → a temp file → the CLI → Anthropic (Claude Code) or OpenAI (Codex) under the user's own account and that provider's terms. Nothing goes to voyput. Settings says so.
- **App.** `Settings` gains `aiProvider` (`openrouter` | `local`), `localEngine`, `localToken`, `localPort`. `ai/client.ts` dispatches each `askAboutImage` to `ai/openrouter.ts` or `ai/local.ts` by `aiProvider`, so Extract, Validate and Rescan follow the choice without their own branches. `aiSetupNeeded` replaces the "has an OpenRouter key" checks on Extract and Review. An extraction made locally records `local/claude` or `local/codex` as its model. The Settings AI card shows the choice, the commands with Copy, the status from `/health` (Found, Not running, Wrong token, Not your voyput-local) and the engine.
- **Mixed content.** An https page calling `http://127.0.0.1` is allowed in Chromium and Firefox (loopback is potentially trustworthy). Recent Chromium asks the user for local network access the first time. Safari has long treated it as mixed content (WebKit bugs 171934, 279249) and behaviour has changed between versions; not verified here. The script does not serve the app (the built app is not one file). Safari users use Chrome or Firefox, or run the app from a clone (`npm run dev`, an http page on 127.0.0.1). Settings says this in one line.

## Alternatives

- npm package or Docker image: rejected by the maintainer; a single file is easier to read before running.
- A root `local/` folder: needs its own test and type-check globs.
- Sending the token as a bearer header: simpler, but a process that grabs the port while voyput-local is stopped would collect the token and then the photos.
- Signed but plaintext photos after a `/health` proof: a process that takes the port between the two requests would still read the photo.
- AEAD alone, without the header MAC: the server could only reject a forged upload after reading it.
- Image as a file plus Claude's `Read` tool: gives the model a file tool; inline base64 needs none.
- Codex on by default with the shell disabled: the remaining tools could not be shown harmless, so it stays opt-in.
- Node's `module.stripTypeScriptTypes` for the build: exists only from Node 22.13, above the repo's minimum.
- A new token on every start: safer if the token leaks, but pairing again after every restart; `--new-token` covers a leak.

## Consequences

- Local works only where the script runs: the same computer as the browser. Phones use OpenRouter.
- The script can only reach engines found at start; installing a CLI later needs a restart.
- With `--codex`, a prompt injected through a photo can still drive Codex's remaining tools; none of them found here reads files, but sub-agents and future Codex versions were not verified. Claude Code gets no tools.
- `--ignore-user-config` means Codex uses its default model, not the one in the user's config. There is no model or effort choice for Local.
- The token is still in the pairing link and in this browser's localStorage; anyone who can read either can sign requests.
- The browser and the script must agree on the time within 60 s; they run on the same computer.
- Each photo costs one extra `/health` round trip on localhost, and the photo is encrypted and decrypted once more (AES-GCM, fast next to the CLI run).
- A photo inside a running CLI's temp dir is plaintext on disk until the job ends; the CLIs need a file or stdin.
- Windows: `.cmd` shims are started through the shell with quoted arguments, and trees are killed with `taskkill`. Not tested.
- Costs are the subscription's limits; the app shows no cost for local runs.
